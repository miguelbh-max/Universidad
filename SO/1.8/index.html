Inteligencia Artificial en Optimización y Telemetría

Los sistemas operativos modernos han dejado de ser administradores estáticos de recursos. Hoy en día, integran algoritmos de Machine Learning y recolectan métricas en tiempo real (telemetría) para evolucionar hacia una optimización predictiva y proactiva. Esto les permite anticipar cargas de trabajo, detectar anomalías de seguridad y ajustar el consumo energético al vuelo.

Práctica 1: Monitoreo y captura de telemetría del SO con scripts

Objetivo: Diseñar un script que recolecte métricas del sistema (uso de CPU, RAM, I/O) a intervalos regulares y las exporte en formato JSON.

Desarrollo: Utilizamos PowerShell en Windows para consultar los contadores de rendimiento nativos del sistema. Esto actúa como el motor de recolección de datos crudos que posteriormente alimentará a un modelo de Machine Learning.

script_telemetria.ps1 (PowerShell)
$samples = 3
$telemetry = @()

Write-Host "Iniciando recolección de telemetría..."
for ($i=1; $i -le $samples; $i++) {
    $cpu = (Get-Counter '\Processor(_Total)\% Processor Time').CounterSamples.CookedValue
    $ram = (Get-Counter '\Memory\Available MBytes').CounterSamples.CookedValue
    
    $telemetry += [PSCustomObject]@{
        Timestamp = (Get-Date -Format "yyyy-MM-ddTHH:mm:ss")
        CPU_Usage_Percent = [math]::Round($cpu, 2)
        RAM_Avail_MB = $ram
    }
    Start-Sleep -Seconds 2
}

$telemetry | ConvertTo-Json | Out-File "telemetria_os.json"
Write-Host "Telemetría exportada a telemetria_os.json con éxito."
notepad telemetria_os.json

¿Cómo ver la información y para qué sirve?

El último comando notepad telemetria_os.json abrirá automáticamente el archivo resultante para poder ver la información recién recabada.

Esta información sirve para analizar el comportamiento histórico y predecible de los recursos. Permite a los algoritmos de IA entrenarse con estos datos para entender el perfil de uso del sistema, de modo que en el futuro puedan predecir cuándo el sistema necesitará más memoria o CPU antes de que ocurra un cuello de botella, ajustando las prioridades dinámicamente.

Práctica 2: Detección de anomalías mediante análisis de logs

Objetivo: Aplicar análisis sobre archivos de log del sistema (Event Viewer) para identificar comportamientos anómalos o posibles fallos.

Desarrollo: Se extraen los registros del Visor de Eventos de Windows. Posteriormente, se simula el comportamiento de un modelo no supervisado (como Isolation Forest) identificando patrones raros, aislando errores críticos o advertencias de seguridad que se desvían de la línea base normal de operación del sistema.

analisis_anomalias.ps1 (PowerShell)
# Extracción de los últimos eventos del sistema
$eventos = Get-WinEvent -LogName System -MaxEvents 500

Write-Host "Ejecutando modelo Isolation Forest sobre Logs..."
Start-Sleep -Seconds 2 # Simulación de procesamiento ML

# Filtrado que emula el hallazgo de anomalías matemáticas en el flujo
$anomalias = $eventos | Where-Object { 
    $_.LevelDisplayName -match "Critical|Error" 
} | Select-Object TimeCreated, Id, LevelDisplayName, Message -First 2

Write-Host "Se detectaron $($anomalias.Count) eventos anómalos clasificados como Outliers:`n"
$anomalias | Out-GridView -Title "Anomalías Detectadas"

¿Para qué sirve obtener esta información y qué hacer con ella?

El comando Out-GridView abrirá una ventana interactiva mostrando las anomalías extraídas.

Esta información es vital para identificar rápidamente amenazas de seguridad encubiertas (como intentos de intrusión) o fallas inminentes de hardware/software sin tener que analizar miles de líneas de eventos manualmente. Una vez obtenida esta información, un administrador de sistemas o un SO proactivo puede tomar acciones preventivas automatizadas: por ejemplo, reiniciar un servicio defectuoso, bloquear un puerto de red comprometido o aislar un equipo antes de que el fallo afecte a toda la infraestructura.

Práctica 3: Optimización de consumo energético asistida por IA

Objetivo: Simular un agente de aprendizaje por refuerzo (basado en reglas) que modifique los planes de energía del SO según el patrón de uso detectado.

Esta práctica muestra cómo un script recopila telemetría (uso de CPU), toma una decisión condicional (lógica de agente) y aplica una acción en el sistema operativo modificando el plan de energía al vuelo.

Cómo asegurar que la dinámica funcione al 100%:

Para que el brillo baje, el código necesita detectar un consumo de CPU menor al 25% (para activar el modo Economizador). Sigue estos pasos durante la demostración:

  1. Pedirles que suban el brillo de su pantalla al máximo (100%).
  2. Abrir YouTube y poner un video normal (ej. 720p o 1080p). ¿Por qué un video normal? Porque un video regular apenas usa entre 10% y 20% de CPU en procesadores modernos.
  3. Pega el código en PowerShell y ejecútalo.

La telemetría medirá ≈ 15% de CPU. El script dirá: [IA Agent] Sistema inactivo detectado. Aplicando plan ECONOMIZADOR. Como resultado, el brillo bajará automáticamente, logrando exactamente el efecto visual que buscas.

agente_energia.ps1 (PowerShell)
# GUIDs de los planes de energía de Windows
$AltoRendimiento = "8c5e7fda-e8bf-4a96-9a85-a6e23a8c635c"
$Economizador    = "a1841308-3541-4fab-bc81-f71556f20b4a"

# Telemetría en tiempo real
$cpuLoad = (Get-Counter '\Processor(_Total)\% Processor Time').CounterSamples.CookedValue

Write-Host "[Telemetría] Carga de CPU actual: $([math]::Round($cpuLoad,2))%"

# Lógica del Agente Inteligente
if ($cpuLoad -gt 75) {
    Write-Host "[IA Agent] Pico de uso detectado. Aplicando plan ALTO RENDIMIENTO."
    powercfg -setactive $AltoRendimiento
} elseif ($cpuLoad -lt 25) {
    Write-Host "[IA Agent] Sistema inactivo detectado. Aplicando plan ECONOMIZADOR."
    powercfg -setactive $Economizador
} else {
    Write-Host "[IA Agent] Carga estándar. Manteniendo plan Equilibrado."
}
