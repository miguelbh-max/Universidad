2.6 ¿Cómo Hacerlo Autoejecutable al Iniciar el Sistema?

Para que un script corra solo al encender el equipo — sin que nadie inicie sesión — se registra como servicio de systemd.

¿Qué es systemd?

Es el gestor de servicios y procesos de arranque de Ubuntu y la mayoría de distribuciones Linux modernas. Decide qué se enciende, en qué orden, y puede mantener corriendo un script de forma permanente.

¿Por qué no basta con cron o .bashrc?

Esas opciones dependen de que alguien inicie sesión o de que el sistema ya esté funcionando. Un servicio de systemd se ejecuta durante el arranque mismo, sin necesidad de una sesión de usuario activa.

Haz clic en cada paso

Registrar el script como servicio

1
Crear el archivo de servicio
▶
Se crea un archivo .service dentro de la carpeta de systemd. sudo nano /etc/systemd/system/mi_tarea.service
2
Recargar systemd y habilitar el servicio
▶
Se avisa a systemd que hay una unidad nueva, y se habilita para que se active en cada arranque. sudo systemctl daemon-reload sudo systemctl enable mi_tarea.service
3
Verificar que corrió solo
▶
Tras reiniciar, se confirma el estado del servicio. sudo systemctl status mi_tarea.service
Contenido del archivo

mi_tarea.service

/etc/systemd/system/mi_tarea.service
[Unit]
Description=Servicio de Autoejecución al Arranque
After=network.target

[Service]
Type=oneshot
ExecStart=/usr/local/bin/monitor-so

[Install]
WantedBy=multi-user.target
Dudas frecuentes

Preguntas y respuestas

Le indica a systemd que el script hace su trabajo y termina (a diferencia de un servicio que corre indefinidamente, como un servidor web). Es el tipo correcto para scripts de una sola tarea, como un firewall o un respaldo.
systemd lo reporta como fallido en systemctl status, y los detalles del error quedan registrados en los logs del sistema, consultables con journalctl -u mi_tarea.service.
Con sudo systemctl disable mi_tarea.service. El archivo .service sigue existiendo, pero deja de activarse en cada arranque.
