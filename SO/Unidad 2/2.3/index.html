2.3 Estructura Formal de un Script, Paso a Paso

Toda la lógica de un script se reduce a tres pasos simples: crearlo, declarar el intérprete y escribir el código.

Haz clic en cada paso

De cero a script funcional

1
Creación con el editor
▶
Se crea el archivo con un editor de texto en la terminal, como nano. nano ~/mi_script.sh
2
El Shebang (línea obligatoria)
▶
La primera línea debe ser exactamente #!/bin/bash. Le ordena al kernel: "carga el intérprete en /bin/bash y pásale el resto del archivo como instrucciones". #!/bin/bash
3
Escribir el código del script
▶
Después del Shebang se escriben los comandos, uno por línea, tal como se teclearían en la terminal. Guardar en nano: Ctrl+O, Enter, salir con Ctrl+X.
Ejemplo completo

monitor_sistema.sh

monitor_sistema.sh
#!/bin/bash
# ========================================================
# Script: monitor_sistema.sh
# Propósito: Diagnosticar recursos del SO Ubuntu
# ========================================================

# 1. Variables del sistema
FECHA=$(date +"%Y-%m-%d %H:%M:%S")
USUARIO=$(whoami)
HOST=$(hostname)

echo "=========================================="
echo " REPORTE DEL SISTEMA - $FECHA"
echo " Servidor: $HOST | Operador: $USUARIO"
echo "=========================================="

# 2. Comprobación de memoria
echo "[*] Estado de la Memoria RAM:"
free -h | grep -E "total|Mem:"

# 3. Comprobación de almacenamiento
echo "[*] Uso de Disco en la Partición Raíz (/):"
df -h / | tail -n 1

exit 0
Dudas frecuentes

Preguntas y respuestas

Sí, excepto la primera línea del archivo cuando forma el Shebang (#!). El resto de las líneas con # son ignoradas por Bash — sirven solo para documentar el código.
Ejecuta el comando dentro de los paréntesis y sustituye esa parte por su resultado. Por ejemplo, $(whoami) se reemplaza por el nombre del usuario actual.
No es obligatorio, pero es buena práctica: indica explícitamente que el script terminó sin errores, lo cual es útil si otro script o proceso revisa el resultado de su ejecución.
