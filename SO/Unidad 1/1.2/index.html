1.2 El Sistema de Permisos de Linux

Todo archivo en Linux vive protegido por tres niveles de acceso. Entender esta lógica es la base para usar chmod con seguridad.

u

User (dueño)

La persona propietaria del archivo.

g

Group (grupo)

El grupo de trabajo asignado al archivo.

o

Others (otros)

Cualquier otro usuario del sistema.

Sintaxis en uso

Ejemplos comunes de chmod

chmod 755 script.sh

Dueño: todo. Grupo y otros: leer/ejecutar. Formato estándar para scripts ejecutables.

chmod 644 datos.txt

Dueño: lee/escribe. Grupo y otros: solo leen. Formato estándar para documentos.

chmod 600 clave.pem

Exclusivo para el dueño. Nadie más puede abrir el archivo — ideal para llaves privadas.

chmod +x script.sh

Notación simbólica: agrega ejecución a todos los niveles (equivale a a+x).

chmod u+x,g-w nota.txt

Agrega ejecución al dueño y retira escritura al grupo, en una sola instrucción.

Dudas frecuentes

Preguntas y respuestas

777 da permiso total (leer, escribir y ejecutar) a cualquier usuario del sistema. Es un riesgo de seguridad grave y casi nunca es lo que realmente necesitas.
La octal (ej. 755) reemplaza los tres niveles completos de una vez. La simbólica (ej. u+x) modifica solo una parte sin tocar el resto de los permisos existentes.
No. chmod cambia permisos; para cambiar el dueño o el grupo se usa chown.
