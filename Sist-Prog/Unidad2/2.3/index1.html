Abstracción de Hardware (HAL)

Separar "qué hace" un componente de "cómo lo hace" por dentro

SUBTEMA 2.3.1

Objetivo

🧩

¿Qué es una HAL?

HAL significa "Hardware Abstraction Layer" (capa de abstracción de hardware). Es una forma de organizar el código en la que se crea una "envoltura" — normalmente una clase en C++ — alrededor de un componente físico, de modo que el resto del programa solo interactúa con esa envoltura y nunca directamente con los pines, registros o protocolos del sensor o actuador.

Contenido

📦

Encapsulamiento modular

Encapsular significa esconder los detalles internos de un componente dentro de una clase, dejando visibles solo los métodos necesarios para usarlo. Quien programa el proyecto no necesita saber si un sensor se comunica por I2C o por un pin analógico — solo llama a un método como leerValor().

🔌

Interfaz vs implementación

La "interfaz" es el conjunto de métodos públicos que ofrece la clase (lo que se ve desde afuera). La "implementación" es el código interno que realmente mueve los pines o lee los registros. Cambiar la implementación no debería obligar a cambiar cómo se usa la clase.

🔄

Portabilidad

Si un proyecto migra de un Arduino UNO a un UNO R4 WiFi, o de un sensor a otro similar, solo es necesario actualizar el interior de la clase de abstracción. El código que usa esa clase en el resto del programa permanece igual.

🧹

Código más limpio

Sin una capa de abstracción, el programa principal termina lleno de configuraciones de pines, registros y protocolos mezclados con la lógica del proyecto. Con una HAL, el loop() se lee casi como una lista de instrucciones en lenguaje natural.

Ejemplo sencillo en Arduino

▸ SITUACIÓN

Un proyecto usa un servomotor para abrir y cerrar una compuerta. En vez de escribir en el loop() los comandos específicos de la librería Servo cada vez que se necesita mover la compuerta, se crea una clase llamada Compuerta con métodos abrir() y cerrar().

Por dentro, la clase Compuerta se encarga de convertir "abrir" en el ángulo correcto del servo y de manejar la librería Servo directamente. El resto del programa solo escribe compuerta.abrir() o compuerta.cerrar(), sin preocuparse de ángulos ni de qué pin está conectado el servo.

Si más adelante se reemplaza el servomotor por un actuador lineal distinto, solo se modifica el interior de la clase Compuerta — el resto del proyecto no cambia ni una línea.
