4.1.2
Brownouts y rebotes

La física no es ideal: los contactos rebotan y el voltaje se cae. El software lo detecta y lo compensa.

Físico: pulsadores + LEDs Tinkercad: mismo circuito (sin rebote real) UNO R4: registros de reinicio
Ir a la práctica ↓Simulador de rebote
Objetivo

Dos fenómenos que engañan al programa

El código asume señales limpias y voltaje estable. En el mundo real ninguna de las dos cosas está garantizada.

🔘

Rebote (bounce)

Presionas una vez y el programa cuenta cuatro. Lo resuelve el software.

📉

Brownout

Arranca el motor, cae el voltaje y el Arduino se reinicia. El software lo previene y lo detecta, el hardware lo corrige.

Parte 1

Rebote de contactos

QUÉ PASA

Metal que rebota

Las láminas del botón chocan y rebotan durante 1 a 20 ms antes de quedarse quietas.

POR QUÉ IMPORTA

loop() es muy rápido

El micro lee el pin miles de veces por milisegundo: ve cada rebote como una pulsación nueva.

SOLUCIÓN

Exigir estabilidad

Aceptar un cambio solo si la lectura se mantiene igual N ms seguidos, medidos con millis().

Simulador: ventana de estabilidad

El driver en C++

  Boton.h · clase
// ===== Driver de un pulsador con filtro de rebote (sin delay) =====
class Boton {
  public:
    Boton(uint8_t pin, unsigned long estableMs = 25) : _pin(pin), _estableMs(estableMs) {}

    void begin() {
      pinMode(_pin, INPUT_PULLUP);              // suelto = HIGH, presionado = LOW
      _cruda = _estado = (digitalRead(_pin) == HIGH);
      _tCambio = millis();
    }

    // Llamar en CADA vuelta de loop(). Nunca usa delay().
    void actualizar() {
      _bajada = _subida = false;
      bool lectura = (digitalRead(_pin) == HIGH);
      if (lectura != _cruda) {                  // la señal cambió: puede ser rebote
        _cruda = lectura;
        _tCambio = millis();                    // reinicia el cronómetro de estabilidad
        if (!lectura) _caidasCrudas++;
      }
      if (lectura != _estado && millis() - _tCambio >= _estableMs) {
        _estado = lectura;                      // estable el tiempo suficiente: se acepta
        if (!_estado) { _bajada = true; _tPresion = millis(); }
        else          { _subida = true; }
      }
    }

    bool sePresiono()     const { return _bajada; }
    bool seSolto()        const { return _subida; }
    bool estaPresionado() const { return !_estado; }
    unsigned long tiempoPresionado() const { return estaPresionado() ? millis() - _tPresion : 0; }
    unsigned long caidasCrudas()     const { return _caidasCrudas; }

  private:
    uint8_t _pin;
    unsigned long _estableMs, _tCambio = 0, _tPresion = 0, _caidasCrudas = 0;
    bool _cruda = true, _estado = true, _bajada = false, _subida = false;   // true = HIGH
};
¿Y por qué no usar delay(50) después de leer?
  • Durante esos 50 ms el programa no hace nada más: ni motores, ni sensores, ni otros botones.
  • Con millis() el filtro cuesta microsegundos por vuelta y todo lo demás sigue funcionando.
  • Alternativa en hardware: capacitor + resistencia + compuerta Schmitt. Funciona, pero cuesta componentes en cada botón.
Tinkercad: sus botones son ideales y no rebotan. El efecto solo se ve con pulsadores reales.
Parte 2

Brownout: caída de voltaje

Una baja momentánea de voltaje, más corta que un parpadeo, basta para que el micro se reinicie o lea basura.

CAUSAS
  • Arranque de motores y servos
  • Bobinas de relevadores
  • USB o fuente débil
  • Cables delgados o largos
SÍNTOMAS
  • Reinicios "misteriosos"
  • Caracteres basura en Serial
  • Lecturas analógicas falsas
  • Salidas que parpadean solas
PISTA

Cuándo ocurre

Si el reinicio coincide siempre con el arranque del motor, casi seguro es un brownout.

Voltaje del Arduino al arrancar el motor

Gráfica ilustrativa: los valores reales dependen de la fuente, el motor y el cableado.

Lo que hace el software

  1. Estado seguro al arrancar: lo primero en setup() es apagar todas las salidas. Si hubo reinicio, nada arranca solo.
  2. Detectar la causa del reinicio: el RA4M1 del R4 guarda en registros por qué se reinició.
  3. Rampas de arranque: subir el PWM poco a poco reduce el pico de corriente.
  4. Escalonar cargas: no encender motor, servo y relevador en la misma vuelta de loop().
  5. Watchdog: si el programa se congela, se reinicia solo (se ve en el tema 4.3).
LO QUE EL SOFTWARE NO ARREGLA
  • Motores y servos con fuente propia, nunca del pin 5V del Arduino
  • Tierra común entre fuentes
  • Cables cortos y gruesos para la potencia
  • Capacitor cerca de la carga
  Rampa no bloqueante
// Arranque suave: la velocidad sube de 5 en 5 cada 20 ms (0 → 200 en 0.8 s)
const uint8_t PIN_ENA = 5;
int velActual = 0, velObjetivo = 200;
unsigned long tRampa = 0;

void actualizarRampa() {                 // llamar en cada vuelta de loop()
  if (velActual == velObjetivo || millis() - tRampa < 20) return;
  tRampa = millis();
  int paso = velObjetivo - velActual;
  if (paso > 5)  paso = 5;
  if (paso < -5) paso = -5;
  velActual += paso;
  analogWrite(PIN_ENA, velActual);
}
  Causa del reinicio · UNO R4
// ===== Causa del último reinicio (solo UNO R4: registros del RA4M1) =====
#if defined(ARDUINO_ARCH_RENESAS)
uint8_t causaReinicio() {
  uint8_t causa;
  if (R_SYSTEM->RSTSR0_b.LVD0RF || R_SYSTEM->RSTSR0_b.LVD1RF || R_SYSTEM->RSTSR0_b.LVD2RF)
    causa = 3;                                   // bajo voltaje (brownout)
  else if (R_SYSTEM->RSTSR1_b.WDTRF || R_SYSTEM->RSTSR1_b.IWDTRF)
    causa = 4;                                   // watchdog
  else if (R_SYSTEM->RSTSR1_b.SWRF)
    causa = 2;                                   // reinicio por software
  else if (R_SYSTEM->RSTSR2_b.CWSF == 0)
    causa = 1;                                   // arranque en frío (se conectó la energía)
  else
    causa = 5;                                   // arranque en caliente (botón RESET)
  R_SYSTEM->RSTSR0 = 0;                          // limpiar banderas para el siguiente arranque
  R_SYSTEM->RSTSR1 = 0;
  R_SYSTEM->RSTSR2_b.CWSF = 1;                   // desde ahora, todo reinicio será "en caliente"
  return causa;
}
void reiniciarPorSoftware() { NVIC_SystemReset(); }
#else                                            // Tinkercad / UNO R3
uint8_t causaReinicio() { return 0; }
void reiniciarPorSoftware() { Serial.println(F("Reinicio por software: solo en UNO R4")); }
#endif
Dato: si el voltaje cae muy bajo, el micro lo registra como un arranque en frío (como si se hubiera desconectado), aunque nadie tocó el cable. Ver "arranque en frío" sin haber desconectado nada es la señal de alarma.
Práctica 4.1.2

Contador honesto y detector de reinicios

El LED verde cambia en cada pulsación filtrada. El LED rojo parpadea al arrancar tantas veces como indique la causa del último reinicio.

ComponenteConexión
PulsadorD2 ↔ GND (usa INPUT_PULLUP, sin resistencia)
LED verdeD12 → 220 Ω → LED → GND
LED rojoD11 → 220 Ω → LED → GND
  Programa principal
// ===== Práctica 4.1.2 — Programa principal =====
// Pega ANTES de esto la clase Boton y el bloque causaReinicio().
const uint8_t PIN_BTN = 2, LED_VERDE = 12, LED_ROJO = 11;
Boton boton(PIN_BTN, 25);             // prueba con 0, 5, 25 y 60 ms

const char* const NOMBRES[] = {
  "desconocida (no es UNO R4)", "arranque en frio", "software",
  "bajo voltaje (brownout)", "watchdog", "arranque en caliente (RESET)"
};

unsigned long pulsaciones = 0, tLed = 0;
bool verde = false, ledRojo = false, reinicioPedido = false;
uint8_t parpadeos = 0;

void setup() {
  uint8_t causa = causaReinicio();    // 1) leerla ANTES que cualquier otra cosa
  pinMode(LED_VERDE, OUTPUT);
  pinMode(LED_ROJO, OUTPUT);
  digitalWrite(LED_VERDE, LOW);       // 2) estado seguro: todo apagado
  digitalWrite(LED_ROJO, LOW);
  boton.begin();
  parpadeos = causa;                  // 3) el LED rojo "dice" la causa

  Serial.begin(115200);
  unsigned long t0 = millis();
  while (!Serial && millis() - t0 < 2000) {}   // espera breve al Monitor serie
  Serial.print(F("Causa del ultimo reinicio: "));
  Serial.println(NOMBRES[causa]);
}

void loop() {
  boton.actualizar();

  if (boton.sePresiono()) {
    pulsaciones++;
    verde = !verde;
    digitalWrite(LED_VERDE, verde ? HIGH : LOW);
    Serial.print(F("Pulsaciones filtradas: ")); Serial.print(pulsaciones);
    Serial.print(F("  | caidas crudas: "));     Serial.println(boton.caidasCrudas());
  }

  // Mantener presionado 3 s = reinicio por software
  if (boton.tiempoPresionado() >= 3000 && !reinicioPedido) {
    reinicioPedido = true;
    Serial.println(F("Reiniciando por software..."));
    Serial.flush();
    reiniciarPorSoftware();
  }
  if (boton.seSolto()) reinicioPedido = false;

  // Parpadeo no bloqueante: 1=frio 2=software 3=bajo voltaje 4=watchdog 5=RESET
  if (parpadeos > 0 && millis() - tLed >= 300) {
    tLed = millis();
    ledRojo = !ledRojo;
    digitalWrite(LED_ROJO, ledRojo ? HIGH : LOW);
    if (!ledRojo) parpadeos--;
  }
}

1Arranque en frío (se conectó la energía)

3Bajo voltaje (brownout)
4Watchdog

  1. Arma el circuito y sube el sketch completo al UNO R4 WiFi.
  2. Rebote: con Boton boton(PIN_BTN, 0) presiona 20 veces y anota pulsaciones filtradas y caídas crudas. Repite con 5, 25 y 60 ms.
  3. Arranque en frío: desconecta y conecta el USB. Cuenta los parpadeos rojos.
  4. Software: mantén el botón 3 s. Al volver, cuenta los parpadeos.
  5. RESET: presiona una sola vez el botón RESET de la placa (dos toques seguidos la ponen en modo de carga).
Tinkercad: el mismo sketch compila en el Uno R3 gracias al #if: la parte del botón funciona y la causa sale como "desconocida".
