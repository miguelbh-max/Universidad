Relevadores y puentes H en software

Del pin suelto a la orden con significado: modela en C++ cómo se comporta el hardware de potencia.

Físico: L298N + motor DC Tinkercad: L293D + LED como relevador Referencia: motor a pasos
Ir a la práctica ↓Simulador del puente H
Objetivo

Del pin a la orden

El resto del programa no debería saber qué pin mueve el motor ni si el relevador se activa con LOW. Eso lo sabe una clase; el programa solo da órdenes.

  Antes: ¿qué hace esto?
digitalWrite(8, HIGH);
digitalWrite(7, LOW);
analogWrite(5, 180);
digitalWrite(4, LOW);   // ¿enciende o apaga?
  Después: se lee solo
motor.adelante(180);
rele.encender();
📖

Legible

El código dice qué pasa, no qué voltaje hay en cada pin.

🛡️

Seguro

Estado inicial y reglas viven en un solo lugar: no se pueden olvidar.

♻️

Reutilizable

Cambias L298N por L293D y loop() no se toca.

Parte 1

Módulo de relevador optoacoplado

Un interruptor mecánico que el Arduino acciona sin tocar eléctricamente la carga.

La señal cruza de un lado a otro solo como luz: así se protege el microcontrolador.

OJO

Activo en BAJO

En casi todos los módulos, LOW = encendido. El driver traduce para que nadie se confunda.

AISLAMIENTO

JD-VCC

Sin el jumper y con fuente aparte, la bobina no comparte tierra con el Arduino.

MECÁNICO

Es lento

Tarda ~5–15 ms en conmutar y tiene vida limitada. Nunca le mandes PWM.

ARRANQUE

Estado seguro

Lo primero en setup(): dejarlo APAGADO.

Prueba: ¿qué nivel enciende el relevador?

El driver en C++

  Relevador.h · clase
// ===== Driver de un módulo de relevador optoacoplado =====
class Relevador {
  public:
    Relevador(uint8_t pin, bool activoEnBajo = true)
      : _pin(pin), _activoEnBajo(activoEnBajo) {}

    void begin() {
      pinMode(_pin, OUTPUT);
      _escribir(false);            // de inmediato: APAGADO (estado seguro)
      _ultimoCambio = millis();
    }

    bool encender() { return _cambiar(true);  }
    bool apagar()   { return _cambiar(false); }
    bool estaEncendido() const { return _encendido; }

  private:
    static constexpr unsigned long TIEMPO_MIN_MS = 100;   // protege los contactos
    uint8_t _pin;
    bool _activoEnBajo;
    bool _encendido = false;
    unsigned long _ultimoCambio = 0;

    // Traduce "encendido/apagado" al nivel eléctrico que pide el módulo
    void _escribir(bool on) {
      digitalWrite(_pin, (on != _activoEnBajo) ? HIGH : LOW);
    }

    bool _cambiar(bool on) {
      if (on == _encendido) return true;                          // ya está así
      if (millis() - _ultimoCambio < TIEMPO_MIN_MS) return false; // conmutación demasiado rápida
      _escribir(on);
      _encendido = on;
      _ultimoCambio = millis();
      return true;
    }
};
¿Por qué 100 ms mínimos? Si un error del programa manda encender/apagar en cada vuelta de loop(), el relevador vibraría y se quemarían los contactos. El driver lo rechaza y devuelve false.
Parte 2

Puente H: dirección y velocidad

Cuatro interruptores electrónicos alrededor del motor. Según cuáles se cierren, la corriente lo cruza en un sentido o en el otro.

🛑

Freno ≠ Libre

Freno pone en corto el motor: se detiene rápido. Libre le quita energía: sigue girando por inercia.

⚡

Nunca invertir de golpe

Pasar de adelante a atrás a toda velocidad produce un pico de corriente. Primero frenar, esperar, luego invertir.

🔌

Detalles del L298N

Quita el jumper de ENA para usar PWM. Pierde ~2 V internamente. Tierra común con el Arduino, siempre.

El driver en C++

  PuenteH.h · clase
// ===== Driver de un canal del puente H (L298N / L293D) =====
class PuenteH {
  public:
    enum class Modo { LIBRE, ADELANTE, ATRAS, FRENO };

    PuenteH(uint8_t en, uint8_t in1, uint8_t in2) : _en(en), _in1(in1), _in2(in2) {}

    void begin() {
      pinMode(_en, OUTPUT);
      pinMode(_in1, OUTPUT);
      pinMode(_in2, OUTPUT);
      libre();                        // estado seguro: motor sin energía
    }

    void adelante(uint8_t vel) { _aplicar(Modo::ADELANTE, true,  false, vel); }
    void atras(uint8_t vel)    { _aplicar(Modo::ATRAS,    false, true,  vel); }
    void frenar()              { _aplicar(Modo::FRENO,    true,  true,  255); }
    void libre()               { _aplicar(Modo::LIBRE,    false, false, 0);   }
    Modo modo() const { return _modo; }

  private:
    uint8_t _en, _in1, _in2;
    Modo _modo = Modo::LIBRE;

    void _aplicar(Modo m, bool a, bool b, uint8_t vel) {
      analogWrite(_en, 0);                    // 1) quitar energía antes de cambiar
      digitalWrite(_in1, a ? HIGH : LOW);     // 2) nueva combinación de IN1/IN2
      digitalWrite(_in2, b ? HIGH : LOW);
      analogWrite(_en, vel);                  // 3) aplicar la orden
      _modo = m;
    }
};
Motor a pasos con L298N (referencia, no está en el laboratorio)

Un motor a pasos bipolar usa los dos canales del L298N: una bobina en OUT1–OUT2 y otra en OUT3–OUT4. Se mueve encendiendo las bobinas en secuencia.

  Ejemplo con la librería Stepper
#include <Stepper.h>
// Motor bipolar de 200 pasos/vuelta en OUT1–OUT4 del L298N (ENA y ENB con jumper)
Stepper pasos(200, 8, 9, 10, 11);     // IN1, IN2, IN3, IN4

void setup() { pasos.setSpeed(60); }  // 60 RPM

void loop() {
  pasos.step(200);    // una vuelta en un sentido    ⚠ step() BLOQUEA hasta terminar
  pasos.step(-200);   // una vuelta en sentido contrario
}
Observa: step() bloquea el programa hasta terminar. En el tema 4.2 se hace sin bloquear, con rampas.

Relevador simulado con un LED (físico y Tinkercad)

5V → resistencia 220 Ω → ánodo del LED · cátodo del LED → D4. Así el LED enciende con LOW, igual que un módulo activo en bajo.

Práctica 4.1.1

Motor y relevador por comandos

Desde el Monitor serie (115200) controlas el motor y el relevador solo con los métodos de las clases.

  Programa principal
// ===== Práctica 4.1.1 — Programa principal =====
// Pega ANTES de esto las clases Relevador y PuenteH.
const uint8_t PIN_ENA = 5, PIN_IN1 = 8, PIN_IN2 = 7, PIN_RELE = 4;

PuenteH   motor(PIN_ENA, PIN_IN1, PIN_IN2);
Relevador rele(PIN_RELE);            // activo en BAJO (como los módulos comerciales)
int velocidad = 150;

void reaplicar() {                   // si el motor gira, aplica la nueva velocidad
  if (motor.modo() == PuenteH::Modo::ADELANTE)   motor.adelante(velocidad);
  else if (motor.modo() == PuenteH::Modo::ATRAS) motor.atras(velocidad);
}

void setup() {
  rele.begin();                      // 1) primero, todo en estado seguro
  motor.begin();
  Serial.begin(115200);
  Serial.println(F("a=adelante r=atras f=freno l=libre +/-=velocidad e=relevador"));
}

void loop() {
  if (!Serial.available()) return;
  char c = Serial.read();
  switch (c) {
    case 'a': motor.adelante(velocidad); break;
    case 'r': motor.atras(velocidad);    break;
    case 'f': motor.frenar();            break;
    case 'l': motor.libre();             break;
    case '+': velocidad = constrain(velocidad + 25, 0, 255); reaplicar(); break;
    case '-': velocidad = constrain(velocidad - 25, 0, 255); reaplicar(); break;
    case 'e':
      if (rele.estaEncendido()) rele.apagar(); else rele.encender();
      break;
    default: return;                   // ignora saltos de línea
  }
  Serial.print(F("Velocidad: "));     Serial.print(velocidad);
  Serial.print(F(" | Relevador: "));  Serial.println(rele.estaEncendido() ? "ON" : "OFF");
}
  1. Tinkercad: Arduino Uno, L293D, motor DC, batería de 9 V y LED con 220 Ω en D4, según la tabla.
  2. Simula: pega el sketch completo, inicia y abre el Monitor serie.
  3. Prueba cada comando (a, r, f, l, +, −, e) y anota qué hace el motor y el LED.
  4. Laboratorio: mismo sketch en el UNO R4 WiFi con L298N, motor y fuente externa. Revisa la tierra común y el jumper de ENA.
  5. Mide: con velocidad 250, cronometra cuánto tarda en detenerse con f y con l. Tres veces cada uno.
