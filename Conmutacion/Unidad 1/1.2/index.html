Cálculo de subredes (Subnetting)

Antes de diseñar cualquier red, hay una pregunta básica que resolver: ¿cómo dividimos un bloque de direcciones IP en partes más pequeñas y manejables? Esa técnica es el subnetting.

¿Qué es subnetear y para qué sirve?

Subnetear es tomar parte del espacio reservado para hosts en una dirección IP y usarlo para crear más redes pequeñas (subredes) en lugar de una sola red grande.

Menos difusión

Subredes más pequeñas significan dominios de broadcast más chicos: menos tráfico innecesario.

Mejor organización

Cada departamento o sucursal puede tener su propio bloque de direcciones.

Uso eficiente del espacio IP

Si solo necesitas 50 hosts, no tiene sentido reservar un bloque completo de 254.

Repaso: máscara de una red Clase C

Las fórmulas que necesitas

FórmulaQué calcula
Subredes creadas = 2ⁿn = bits robados a la porción de host
Hosts por subred = 2ᵐ − 2m = bits de host restantes; se restan red y broadcast
Salto entre subredes = 256 − máscara decimalCada cuántas direcciones empieza la siguiente subred
Corrección sobre el material original Versiones antiguas de este tema también restan 2 a las subredes (2ⁿ−2). Esa regla es de un estándar obsoleto (antes de RFC 1878); el equipo moderno (Cisco IOS, Packet Tracer) usa todas las subredes sin restar. Por eso aquí 2ⁿ es para subredes y el −2 se aplica solo a hosts.

Ejemplo resuelto

Red 192.168.1.0/24, crear 4 subredes con mínimo 50 hosts cada una.

1

Bits a robar

2ⁿ ≥ 4 → n=2 bits. Máscara pasa de /24 a /26 (255.255.255.192).

2

Hosts por subred

8−2=6 bits libres → 2⁶−2 = 62 hosts (cumple el mínimo de 50).

3

Salto entre subredes

256−192=64 → bloques de 64 direcciones: 0, 64, 128, 192.

Ejemplo fácil Imagina 256 casas numeradas en una calle. Subnetear es levantar una reja cada 64 casas para formar 4 colonias: cada una con su entrada (red), su salida común (broadcast), y el resto para vecinos (hosts).
