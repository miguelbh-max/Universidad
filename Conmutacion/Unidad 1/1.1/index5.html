+ Cálculo de subredes (Subnetting)

Antes de crear VLANs, enlaces troncales o cualquier diseño de red, hay una pregunta más básica que resolver: ¿cómo dividimos un bloque de direcciones IP en partes más pequeñas y manejables? Esa técnica es el subnetting, y es la base para entender el direccionamiento que usan las páginas anteriores de este tema.

¿Qué es subnetear y para qué sirve?

Subnetear es tomar parte del espacio reservado para identificar hosts en una dirección IP y usarlo para crear más redes pequeñas (subredes) en lugar de una sola red grande. Esto evita que una red crezca sin control y se vuelva difícil de administrar.

📉 Menos difusión

Subredes más pequeñas significan dominios de broadcast más chicos: menos tráfico innecesario circulando por toda la red.

🗂️ Mejor organización

Cada departamento, piso o sucursal puede tener su propio bloque de direcciones, facilitando la administración y el diagnóstico de fallas.

♻️ Uso eficiente del espacio IP

Si solo necesitas 50 hosts, no tiene sentido reservar un bloque completo de 254. El subnetting ajusta el tamaño a lo que realmente necesitas.

Repaso rápido: la máscara de una red Clase C

Toda dirección IPv4 tiene 32 bits repartidos en 4 octetos. En una red Clase C por defecto, los primeros 24 bits identifican la red y los últimos 8 identifican el host — de ahí la notación /24 y la máscara 255.255.255.0.

Las fórmulas que necesitas

FórmulaQué calcula
Subredes creadas = 2ⁿn = bits que le “robamos” a la porción de host
Hosts por subred = 2ᵐ − 2m = bits de host que quedan; se restan 2 porque la primera dirección (red) y la última (broadcast) de cada subred no se asignan a equipos
Salto entre subredes = 256 − valor decimal de la máscaraIndica cada cuántas direcciones empieza la siguiente subred
Mejora sobre el material original Vas a encontrar versiones de este tema que también restan 2 a las subredes (2ⁿ − 2), excluyendo la primera y la última. Esa regla viene de un estándar antiguo que prohibía usar la subred "todo-ceros" y la "todo-unos". Desde hace más de una década (RFC 1878) prácticamente todo equipo moderno — incluido Cisco IOS y Packet Tracer — permite usarlas todas sin problema. Por eso aquí usamos 2ⁿ sin restar para las subredes, y dejamos el −2 únicamente para los hosts, que sí siguen perdiendo su dirección de red y de broadcast.

Ejemplo resuelto paso a paso

Dada la red 192.168.1.0 /24, crea 4 subredes con un mínimo de 50 hosts cada una.

1

¿Cuántos bits hay que robarle a la porción de host?

Necesitamos al menos 4 subredes → buscamos el menor n tal que 2ⁿ ≥ 4 → n = 2 bits. Al pasarlos de la porción de host a la de red, la máscara cambia de /24 a /26, es decir, de 255.255.255.0 a 255.255.255.192.

2

¿Cuántos hosts quedan por subred?

Quedaron 6 bits de host libres (8 − 2 = 6) → 2⁶ − 2 = 62 hosts utilizables por subred. Como se pedía un mínimo de 50, esta máscara cumple perfectamente.

3

¿Cuál es el salto entre subredes?

256 − 192 = 64 → cada subred ocupa un bloque de 64 direcciones, empezando en 0, 64, 128 y 192.

Cada bloque de 64 direcciones es una subred completa (incluye su dirección de red y su broadcast).

Ejemplo fácil Imagina las 256 direcciones como una calle con casas numeradas del 0 al 255. Subnetear es levantar una reja cada 64 casas para formar 4 colonias independientes. Cada colonia tiene una entrada oficial (dirección de red), una salida común para anuncios generales (broadcast), y el resto de las casas son para los vecinos (hosts).
